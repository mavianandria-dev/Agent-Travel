# 2026-10-25 — Sesi 6

## Tujuan

Menyelesaikan Fase A: mengubah backend `code.gs` dari rencana “proxy wajib” menjadi **mode direct** yang aman, lalu menyiapkan proyeksi publik, filter baris per peran, aksi akun tervalidasi, throttling, dan pencabutan token. Frontend belum disentuh.

## Keputusan

### 1. Direct mode, tanpa proxy database

Browser memanggil Web App `/exec` langsung. `REQUIRE_PROXY_KEY` default `false`; `proxyKey` menjadi opsional dan hanya dipertahankan untuk kemungkinan proxy di masa depan. Jika klien mengirim `proxyKey`, nilainya tetap harus benar.

Alasan: tidak ada Cloudflare Worker/proxy DB; spreadsheet tetap privat; Web App publik dengan **Execute as Me / Access Anyone**. Karena Apps Script tidak membaca header dan tidak menangani `OPTIONS`, request memakai `POST` dengan `Content-Type: text/plain;charset=utf-8` agar tidak memicu preflight.

**Belum terbukti:** CORS dari origin GitHub Pages harus diprobe setelah deploy. Jika respons tidak terbaca, direct mode batal dan perlu proxy alternatif.

### 2. Proyeksi publik menggantikan record penuh

Bootstrap publik hanya mengirim `banners`, `routes`, `reviews`, `agencies`, `vehicles`, `schedules` yang sudah diproyeksikan:

- `agencies` tanpa `kyc`, `bank`, rekening, dokumen, dan field internal.
- `vehicles` tanpa data pemilik, dokumen, chassis/engine, pajak/KIR.
- `schedules` tanpa pengemudi; ditambah `takenSeats` hasil hitung server.
- Agensi `pending` beserta armada/jadwal/ulasannya tidak masuk katalog publik.

Keputusan ini menutup kebocoran KYC/NIK/rekening yang sebelumnya ada di bootstrap publik.

### 3. Filter baris per peran, bukan sekadar filter koleksi

- `pelanggan`: hanya booking/payment/notifikasi/tiket/audit miliknya; katalog publik + `vouchers` untuk checkout.
- `pengemudi`: hanya jadwal yang ditugaskan, booking jadwal tersebut, kendaraan jadwal tersebut, maintenance dirinya; rekan sesama jadwal hanya `id/name/phone/photo/rating/status`.
- `agen`: agensi sendiri penuh; agensi/armada/jadwal lain hanya proyeksi publik; booking/payment/ledger/route request/maintenance/tiket dibatasi agensinya.
- `superadmin`: semua koleksi, tetapi record `users` tetap disanitasi.

Notifikasi `to: 'all'` ikut dikirim ke semua peran.

### 4. Aksi akun tervalidasi di server

Ditambahkan `register`, `adminCreateUser`, dan `adminSetPassword`; `changePassword` diperketat. Aturan penting:

- Password baru minimal **8** karakter (frontend masih 6; diperbarui di Fase B).
- `register` publik hanya pelanggan/agen. Agen membuat agensi + user `pending`, tanpa token.
- Satu agensi satu akun agen; akun pengemudi harus cocok dengan `drivers.userEmail`, agensi sudah punya agen aktif, dan pengemudi nonaktif tidak boleh punya jadwal aktif.
- Email unik lintas user; role `superadmin` tidak bisa dibuat lewat API.
- Semua aksi menaikkan `rev` koleksi yang ditulis agar commit klien dengan revisi basi tidak menimpa perubahan server.

### 5. Throttling berbasis `CacheService`

Login: 5 kegagalan/15 menit per email → blokir 15 menit. Ganti password: 5 kegagalan → blokir 15 menit. Registrasi: 30/jam global. Cache bersifat best effort; rate limit per IP tetap pekerjaan proxy.

### 6. Pencabutan token lewat `tokenVersion`

Payload token menambah `pv`. Ganti password/reset admin menaikkan `tokenVersion` user sehingga token lama langsung ditolak. `tokenVersion` tidak pernah dikirim ke klien dan dipertahankan saat commit profil user.

### 7. `commit` tetap superadmin-only, dengan pengaman tambahan

- Field password/`tokenVersion` yang tidak dikirim klien disalin dari record lama; commit profil tidak menghapus hash.
- Superadmin tidak boleh menghapus akunnya sendiri.
- `bookings`/`payments` tetap tidak boleh ditulis lewat commit sampai validasi kursi/harga/pembayaran server-side ada.

- Memperbarui `google-apps-script/README.md`: mode direct, probe CORS, kontrak API, proyeksi, throttle, risiko, langkah Fase B–D.

- Tidak mengubah frontend, `seed.gs`, atau `appsscript.json`.

## Verifikasi

- `node google-apps-script/local-tests/mock-harness.mjs` → **PASS: 155, FAIL: 0**.
- Cakupan: mode direct/proxy opsional, migrasi plaintext → hash, token tamper/expired/revoked, bootstrap lima peran, proyeksi tanpa KYC/NIK/rekening, filter baris, `takenSeats`, agensi pending, commit + konflik + secret preservation + self-delete guard, register, admin create/reset, throttle login/ganti password, `doGet`/`doPost`, pemindaian kebocoran secret.
- Belum dijalankan di akun Google nyata. **CORS belum terbukti.**

## Risiko dan keterbatasan

- Direct mode bergantung pada CORS Apps Script; wajib probe sebelum Fase B.
- Frontend masih `localStorage` dan membandingkan password di browser.
- Validasi booking/kursi/pembayaran server-side belum ada.
- Commit multi-koleksi belum atomik.
- `takenSeats` menghitung dari seluruh booking pada setiap bootstrap publik; pantau performa.
- Registrasi/aksi admin belum menulis audit/notifikasi selamat datang.
- Rekening agensi tidak ada di proyeksi publik; perlu aksi scoped untuk instruksi transfer.
- `CacheService` bisa kosong; throttle bukan jaminan mutlak.
- 2000 iterasi hash adalah kompromi batas CPU Apps Script.

## Langkah berikutnya

1. Pengguna deploy Web App + `setupBackend()`, lalu probe CORS dari origin produksi.
2. Jika lolos: **Fase B** — adapter baca frontend (`sheetsApi.js`, bootstrap async, token sesi, cache memori).
3. **Fase C** — aksi tulis per peran + validasi booking/kursi/pembayaran + audit/notifikasi + rekening scoped.
4. **Fase D** — pindah semua peran ke `VITE_DATA_MODE=sheets`; `localStorage` hanya untuk session/lang/draft checkout/guest support.
