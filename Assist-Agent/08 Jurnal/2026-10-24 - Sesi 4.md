# 2026-10-24 — Sesi 4

## Tujuan

Menyiapkan database produksi minimal di Google Sheets untuk TransAceh, dimulai dari seed yang benar-benar bersih tanpa akun, armada, rute, jadwal, booking, atau transaksi demo.

## Keputusan

### 1. Seed dulu, API kemudian

Tahap ini hanya membuat struktur spreadsheet dan satu akun superadmin. `code.gs` untuk API baca/tulis belum dibuat. Aplikasi React tetap memakai `localStorage` sampai adapter dan bootstrap async selesai.

### 2. Satu baris = satu record JSON

Setiap tab koleksi memakai kolom `id`, `ord`, `json`, dan `updated_at`. Nested object seperti KYC, layout kursi, penumpang, dan pesan support tetap berada di dalam JSON. `_meta` memakai `key`/`value`.

Alasannya: struktur record antar-koleksi sangat berbeda; memaksakan kolom relasional akan membuat migrasi rapuh.

### 3. Data produksi minimal

Seed hanya membuat:

- satu user `superadmin` dari Script Properties;
- `settings.platformFee` default 8%;
- `fees` legacy;
- satu audit entry `seed_production`.

Semua koleksi operasional lain dibuat dengan header kosong.

### 4. Kredensial tidak masuk source code

Nama, email, telepon, dan password admin diisi lewat Script Properties. Password minimal 12 karakter. Saat ini password masih ditulis ke field `pass` di JSON `users` karena autentikasi frontend lama membandingkannya di client; ini harus diganti sebelum data nyata masuk.

### 5. Seed aman dan idempoten

- Terikat ke spreadsheet aktif, tanpa spreadsheet ID.
- Memakai `LockService`.
- Berhenti jika `_meta` atau tab koleksi sudah berisi data.
- Header kosong boleh ditulis ulang.
- `validateDatabase()` memeriksa header, JSON, ID, `ord`, `updated_at`, revisi, superadmin, dan platform fee.
- Tidak ada reset otomatis; backup dilakukan manual.

## Perubahan

- Menambah `google-apps-script/seed.gs`.
- Menambah `google-apps-script/appsscript.json`.
- Menambah `google-apps-script/README.md`.
- Tidak mengubah frontend, `DB.load/save`, atau data `localStorage`.

## Verifikasi

- `appsscript.json` lolos parse JSON.
- `seed.gs` lolos `node --check`.
- Mock test dengan `SpreadsheetApp`, `PropertiesService`, `LockService`, dan `Utilities` lulus:
  - 20 tab dibuat;
  - `Sheet1` kosong dihapus;
  - satu admin, satu settings, satu fees, satu audit;
  - 15 koleksi lain hanya header;
  - `validateDatabase()` mengembalikan `ok: true`;
  - seed kedua diblokir karena data sudah ada.
- Belum dijalankan di akun Google nyata; langkah berikutnya adalah eksekusi manual di spreadsheet pengguna.

## Risiko

- Field `pass` masih plaintext.
- Web App belum boleh dipublikasikan.
- Cache adapter belum ada, jadi belum ada baca/tulis remote dari aplikasi.
- Validasi kapasitas dan pembayaran harus di server saat booking nyata.
- Google Sheets bukan database transaksional; perlu backup dan pengawasan kuota.

## Langkah berikutnya

1. Pengguna menjalankan seed di spreadsheet kosong dan memeriksa hasil `validateDatabase()`.
2. Setelah seed terverifikasi, buat `code.gs` untuk read/write, autentikasi, revisi, dan lock.
3. Tambahkan proxy Cloudflare Worker.
4. Ubah `db.js` menjadi cache adapter dan pindahkan bootstrap ke async.
