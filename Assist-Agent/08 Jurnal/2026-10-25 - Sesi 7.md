# 2026-10-25 — Sesi 7

## Tujuan

Menyelesaikan Fase B dan C: menyambungkan frontend ke Google Sheets, membuat jalur tulis `sync` ter-scope, memvalidasi booking/payment/ledger di server, serta menyiapkan rollback dan pemulihan sesi.

## Keputusan

### 1. Satu aksi `sync`, bukan menulis ulang semua `DB.save`

Frontend tetap memakai `DB.save`/`DB.load`; `db.js` menyimpan cache optimistis, menghitung diff per koleksi, mengirim batch dengan `baseRev`, dan rollback jika server menolak. Ini menghindari perubahan di 188 call site dan menjaga API domain tetap sama.

### 2. Transport direct

Browser POST JSON sebagai `text/plain;charset=utf-8` ke Apps Script `/exec`; token di body. Apps Script tidak membaca header dan tidak menangani `OPTIONS`. `proxyKey` opsional lewat `REQUIRE_PROXY_KEY` (default `false`); key non-empty yang salah tetap ditolak.

### 3. Validasi server berlapis

`apiSync_` memuat referensi lintas koleksi lebih dulu, memvalidasi bentuk, revisi, kepemilikan, field terlarang, relasi, nominal, transisi status, dan kursi. Penulisan baru dilakukan setelah semua koleksi lolos. `apiSyncCrossValidate_` memeriksa kursi ganda, `blockedSeats`, dan kursi nonaktif.

Validasi penting:

- Booking baru hanya `pending`; pelanggan hanya atas nama sendiri; pengemudi hanya `source:'driver'` dengan `createdBy` dirinya; agen tidak boleh membuat booking.
- Subtotal = harga jadwal × kursi; diskon sesuai voucher; total = subtotal − diskon; jumlah penumpang = jumlah kursi.
- Update booking tidak boleh mengubah total/subtotal/diskon/identitas; status mengikuti transisi; pindah jadwal/kursi hanya lewat maintenance.
- Refund dibatasi kebijakan agen; status refund/`refundPaidAt` hanya admin; refund yang sudah dibatalkan tidak boleh dinaikkan.
- Payment: satu per booking, nominal = total booking, fee = `splitFare`, status baru `pending`, refund tidak melebihi refund booking.
- Ledger: hanya booking lunas, satu per booking, payment harus `paid`, identitas dan nominal harus cocok, pindah hanya lewat maintenance.
- Voucher agen hanya berlaku pada jadwal agensinya; voucher global/agen lain hanya boleh diubah `used`.
- Rute/armada/jadwal/pengemudi/maintenance dibatasi agensi dan relasi; driver yang masih terpasang tidak boleh dihapus.
- Tiket support divalidasi field-level; pesan CS palsu, penutupan paksa, dan tiket guest tersinkron ditolak.
- Notifikasi mode Sheets hanya self-only; notifikasi lintas pengguna belum otomatis.

### 4. Sesi kedaluwarsa dan rollback

`AppContext` memasang `DB.setSyncErrorHandler`. `REV_CONFLICT`/`SEAT_CONFLICT` memuat ulang snapshot; `UNAUTHORIZED`/`ACCOUNT_BLOCKED` membersihkan token/sesi/cache/draft checkout, kembali ke `home`, lalu memuat snapshot publik. Logout melakukan flush sebelum menghapus token.

### 5. Secret dan password

`apiSyncPrepareUsers_` menyalin secret lama sebelum diff; password baru di-hash dan menaikkan `tokenVersion`. Password plaintext dihapus dari cache/snapshot user setelah sync sukses.

## Perubahan

- Backend `code.gs` naik ke **1.2.0**: `sync`, validator per koleksi, `apiSyncCrossValidate_`, refund expectation, uniqueness payment/ledger, dan guard commit.
- Frontend: `sheetsApi.sync`, `loadSnapshot` menghidrasi revisi, `db.js` cache/diff/rollback, `boot.js`/`BootGate`, `AppContext` handler error, `support.js` tiket guest lokal, `Search.jsx` voucher per agensi, `agen/Setting.jsx` voucher agen.
- Patch keamanan: whitelist field booking/payment/ledger baru, guard `paidOutAt`/`dicairkan`, larangan pengurangan voucher tanpa pembatalan, pembatasan self-update pengemudi dan approval maintenance. Hold booking baru ditentukan server dan tidak boleh diperpanjang; pembayaran tidak boleh lunas saat booking masih pending.
- Harness diperluas menjadi **265 asersi**.
- Dokumentasi [[Database Google Sheets]], [[Build dan Deploy]], dan `google-apps-script/README.md` diperbarui.

## Verifikasi

- `node google-apps-script/local-tests/mock-harness.mjs` → **PASS: 265, FAIL: 0**.
- `npm run build` → lulus, 1998 modul, output `dist`.
- Probe Node ke Web App lama: health `1.1.0`; `sync` → `UNSUPPORTED_ACTION`. Header respons Node memuat `Access-Control-Allow-Origin: *`, tetapi CORS browser belum diuji.

## Risiko dan keterbatasan

- Web App ter-deploy masih 1.1.0; `sync` belum aktif.
- CORS dari GitHub Pages belum diverifikasi di browser.
- Lifecycle (`cleanupHolds`, jadwal lampau, resolusi maintenance) dimatikan di mode Sheets dan belum ada trigger server-side.
- Multi-koleksi belum atomik; validasi semua dulu, tetapi penulisan per tab.
- Notifikasi lintas pengguna belum otomatis.
- Media/KYC base64 berpotensi melebihi batas 45.000 karakter/50.000 sel.
- `commit` tetap melewati validator domain; hanya superadmin/darurat.
- Rate limit cache best effort.

## Langkah berikutnya

1. Deploy `code.gs` 1.2.0 dan probe CORS + `sync` dari browser.
2. Uji end-to-end semua peran dengan data sintetis.
3. Pindahkan lifecycle ke trigger Apps Script/server-side atau setujui batasannya.
4. Putuskan media/KYC (Drive privat + endpoint media) dan notifikasi lintas pengguna.
5. Setelah lulus, ubah `VITE_DATA_MODE=sheets`; jangan mencampur mode.
6. Backup spreadsheet dan pantau kuota.
