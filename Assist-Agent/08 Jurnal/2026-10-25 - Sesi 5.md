# 2026-10-25 — Sesi 5

> [!warning] Sebagian keputusan sudah digantikan
> Sejak [[2026-10-25 - Sesi 6]], mode default adalah **direct** (tanpa proxy database), bootstrap memakai proyeksi publik + filter baris, dan aksi akun tervalidasi sudah ditambahkan. Keputusan #2 (proxy wajib) dan #4 (ruang baca) di bawah adalah catatan historis; lihat Sesi 6 untuk kontrak yang berlaku.

## Tujuan

Meneruskan milestone setelah seed produksi tervalidasi: menulis ulang `code.gs` menjadi backend API yang benar, aman, dan bisa diuji di lokal sebelum dipasang ke akun Google.

## Keputusan

### 1. API generik per koleksi, bukan RPC per endpoint

`code.gs` tidak meniru model domain frontend. Ia hanya menyediakan commit generik per koleksi dengan validasi minimal yang sadar skema. Validasi domain (konflik kursi, ketentuan jadwal) menyusul sebagai lapisan tambahan, bukan re-embed seluruh `domain.js` ke server.

### 2. Semua aksi non-`health` dijaga `proxyKey`

Aksi `health` satu-satunya yang publik. Aksi lain, termasuk `login`, wajib mengirim `proxyKey` yang cocok dengan `API_PROXY_KEY` di Script Properties. Alasannya: Web App Apps Script tidak bisa membaca header HTTP, jadi gerbang harus lewat body, dan selama Worker proxy belum ada, endpoint jangan menerima siapa pun.

### 3. Password hash berlapis + migrasi plaintext otomatis

Hash memakai HMAC-SHA512 berulang (salt acak + pepper + 2000 iterasi, algoritma `hmac-sha512-iter-v1`). Pada login pertama user legacy yang masih menyimpan `pass` plaintext dari seed, password diverifikasi lalu segera diganti `passHash`+`passSalt`+`passIter`+`passAlgo` dan field `pass` dihapus dari JSON `users`.

### 4. Akses baca per peran, tulis hanya superadmin

`bootstrap` mengembalikan koleksi sesuai ruang baca peran. `bookings`, `payments`, dan `ledger` sengaja belum diberikan ke non-superadmin karena butuh filter per-pemilik. `commit` saat ini hanya untuk `superadmin`; peran lain menyusul setelah validasi server-side per record siap.

### 5. Secret dibuat sekali dan tidak pernah dicetak

`setupBackend()` dijalankan dari editor, bukan lewat HTTP. Ia mengisi `API_PROXY_KEY`, `API_TOKEN_SECRET`, `PASSWORD_PEPPER`, `TOKEN_TTL` di Script Properties dan tidak menimpa nilai yang sudah ada. Nilai tidak pernah masuk log maupun output apapun.

### 6. Commit pesimistis-lock via revisi koleksi

`changes` berformat `{koleksi: {baseRev, upserts, deletes}}`. `baseRev` harus persis sama dengan `rev.<koleksi>` di `_meta`, kalau tidak `REV_CONFLICT`. Delete diproses sebelum upsert; upsert menang bila id sama. Urutan baris lama dipertahankan; record baru ditambahkan di akhir. Semua penulisan berada di dalam `LockService.getScriptLock()`.

## Perubahan

- Menulis ulang `google-apps-script/code.gs` dari nol (~820 baris) memakai prefix `api`/`API_` agar tidak berbenturan dengan global `seed.gs`.
- Menambah `google-apps-script/local-tests/mock-harness.mjs`: harness Node + `vm` yang mem-mock `SpreadsheetApp`, `PropertiesService`, `LockService`, `Utilities`, `ContentService`, dan `Logger`, lalu menjalankan 50 asersi.
- Memperbarui `google-apps-script/README.md`: status, peringatan keamanan, langkah pemasangan `code.gs`, dan kontrak API lengkap.
- Memperbarui [[Database Google Sheets]]: status, kontrak API, dan daftar sumber dengan nomor baris baru.
- Tidak mengubah `seed.gs`, `appsscript.json`, frontend, atau apa pun di `transaceh-react/`.

## Defect dari draf lama yang dibetulkan

Draf `code.gs` lama punya banyak cacat; versi baru memperbaiki semuanya:

- `apiParseRequest_` memakai variabel yang tidak terdefinisi; `ALLOWED` implisit global.
- Password dibaca setelah field-nya sudah di-strip dari request.
- `API_WRITE_ACCESS.agen` menulis ke koleksi `accounts` yang tidak ada dan kehilangan `users`.
- `results.revs` tertukar antara array dan objek; `apiResetPassword_` memanggil `.slice()` pada fungsi.
- PBKDF2 ad-hoc merangkai `pepper:password` dengan blok/counter yang salah dan `passIter || 0`.
- Record buka/tulis membawa `_row/_ord/_id` ke dalam JSON Sheets.
- Validasi seat conflict mengabaikan `scheduleId`.
- `apiEnsureProps_` meregenerasi secret dengan `Math.random` pada setiap request.
- `apiHealth_` mencari `rev.schemaVersion` padahal key di `_meta` adalah `schemaVersion`.

## Verifikasi

- 50 asersi mock lulus semua (`PASS: 50, FAIL: 0`):
  - `setupBackend` menghasilkan 4 Script Properties dengan panjang memadai.
  - `health` publik, tidak membocorkan secret.
  - Login legacy superadmin sukses dan melakukan migrasi plaintext → hash; plaintext hilang dari tab `users`.
  - Login password salah ditolak; login kedua via hash path sukses.
  - `session` valid/tampered/expired/proxy salah lintas kasus.
  - `bootstrap` superadmin (19 koleksi), publik (4 koleksi), agen (tanpa `bookings`/`payments`/`ledger`); `users` sudah disanitasi.
  - `commit` happy path, rev naik, konflik revisi, commit oleh agen ditolak, koleksi tidak dikenal, changes kosong, record tanpa id, id duplikat, field rahasia, delete koleksi.
  - `changePassword` alur ganti/berhasil login password baru/password lama ditolak/sama dengan baru/terlalu pendek.
  - Tidak ada secret maupun plaintext password yang muncul di response manapun dan di log.
  - Setelah semua aksi, tab `users` tidak lagi menyimpan plaintext.
- Belum dijalankan di akun Google nyata. Tahap berikutnya membutuhkan deploy web app oleh pengguna.

## Risiko dan keterbatasan yang disengaja

- `commit` belum memvalidasi konflik kursi atau ketentuan jadwal. Frontend tidak boleh menulis `bookings` lewat API sebelum validasi ini ada.
- Jika penulisan tab gagal di tengah batch multi-koleksi, sebagian koleksi bisa sudah tertulis sementara `_meta.rev` belum diperbarui. Aman untuk commit kecil per-kasus; transaksi lintas-koleksi penuh belum dijamin.
- Tidak ada rate limit pada `login`; ini diserahkan ke Worker proxy nanti.
- `Token TTL` default 12 jam; rotasi secret manual.
- Secret berada di Script Properties yang hanya bisa dibaca editor proyek; jangan menambah kolaborator editor tanpa kebutuhan.

## Langkah berikutnya

1. Pengguna memasang `code.gs` (copy ke editor), menjalankan `setupBackend()`, lalu deploy Web App (execute as Me, akses Anyone) dan menguji `health` via GET.
2. Login sekali sebagai superadmin lewat API supaya migrasi password plaintext terjadi di spreadsheet nyata.
3. Bangun proxy Cloudflare Worker di `transaceh-react/worker/` yang menyimpan `API_PROXY_KEY`, menambah CORS, origin check, dan rate limit.
4. Ubah `transaceh-react/src/lib/db.js` menjadi cache adapter dengan antrean tulis, mempertahankan tanda tangan `DB.load`/`DB.save`.
5. Pindahkan bootstrap aplikasi ke alur async di `main.jsx`/`AppContext`; pertahankan data lokal-only (session, lang, draft checkout, identitas guest support) di `localStorage`.
